# 002 · Passkeys в Safari через KeePassXC

Прочитать design.md, затем выполнять tasks.md сверху вниз. Для финальной проверки в фоне требуется 001. Хранилище ключей и подтверждение операций принадлежат KeePassXC.

| ID | Требование и критерий приёмки |
|---|---|
| PK-1 | Переключатель в popup по умолчанию выключен. Настройка сохраняется. Текст на en/de поясняет применение после перезагрузки страницы. При выключении работает штатный WebAuthn Safari. |
| PK-2 | На основном HTTPS-документе явный credentials.create с publicKey создаёт запись после подтверждения в KeePassXC. Сайт принимает регистрацию. |
| PK-3 | credentials.get завершает вход с сохранённым ключом. Проверить выбор из двух записей, allowCredentials и ключ, созданный официальным KeePassXC-Browser для того же RP. |
| PK-4 | В iframe, при conditional mediation, без publicKey и для неподдерживаемых опций вызов обрабатывает Safari. После передачи в KeePassXC автоматического повтора или второго диалога нет. |
| PK-5 | Проверяются происхождение документа и допустимость RP ID. Запрос и результат принадлежат одному документу. Канал сайта допускает только регистрацию и вход. |
| PK-6 | Отказ, блокировка базы, тайм-аут, отмена, навигация и потеря моста завершают запрос или освобождают ресурсы документа. Popup различает остановленный мост, отсутствие сопряжения и несовместимую версию KeePassXC. |
| PK-7 | С закрытым окном приложения сайт принимает регистрацию и проверяет подпись при следующем входе. Существующие сохранение и заполнение паролей, TOTP работают. |

Системный провайдер AutoFill macOS за пределами первой версии.
